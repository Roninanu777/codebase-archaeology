## What the eval caught before it caught anything else

Two real defects surfaced on the first run and were fixed same-session:

1. **Sparse leg was AND-semantics.** `websearch_to_tsquery` treats spaces as
   `&`, so natural-language questions containing "why" matched almost nothing.
   Fixed: tokenize client-side, join with `or`. Effect: context-API case went
   from absent to rank 9; uMS and act cases jumped to rank 1.
2. **The corpus silently excluded subject-only commits.** The tiny-body filter
   dropped "New context API (#11818)" entirely. Fixed: subjects carrying a PR
   reference are always included; incremental embed absorbed 18 recovered
   chunks without a re-index.

## Corpus gaps, confirmed not guessed

Two cases were reclassified from `retrieval` to `known_gap` after inspection
showed their ground-truth commits carry no rationale text (bodies echo PR
titles). This is DESIGN.md Problem 2 measured: the written reasoning for lanes
(#19108/#15387) and the render→createRoot migration lives in PR discussions
and external posts, i.e., exactly what tier-2 ingestion will add. The system's
current honest behavior is retrieving adjacent context while flagging staleness,
not inventing rationale.

## Known costs / next fixes

- Abstention-on-missing-symbol costs ~9s because auto-search parses up to 4,000
  files before giving up. Cheap fix queued: bail after N consecutive misses or
  require --file when repo exceeds a size threshold.
- First query pays model-load (~11s); warm queries run 40-90ms end-to-end.
- Recall set is small (3). Tier-2 data plus the dig's remaining functions grow
  it; target 20+ retrieval cases before the writeup.
